# AIDOG 价格提醒器初始需求文档

## 1. 目标

第一版先只做一个固定资产的提醒模块，围绕 `AIDOG` 跑通完整链路：

1. 从 DEX Screener 获取 AIDOG 的实时价格和池子数据。
2. 按固定频率保存价格快照。
3. 支持两类提醒：
   - 价格跌到用户设置阈值时提醒
   - 在指定时间窗口内涨跌幅达到用户设置阈值时提醒
4. 通过飞书 Webhook 发送提醒消息。

当前版本暂不做：

1. 任意代币搜索
2. 多链统一抽象
3. 用户体系和多用户权限
4. 页面 UI

## 2. 监控对象

第一版固定监控 AIDOG，不做动态选币。

- 代币名称：`AIDOG`
- 链：`Base`
- Token Address：`0x80394ae69f14444605032a7f2d74c8ab7d16a51d`
- 当前主池：`0xDaAe8AfdEb4d31e4F6A0cDB9d490D4188d48C0A9`
- DEX：`Uniswap`

说明：

1. 系统内部所有判断基于 `chain + tokenAddress` 和固定 `pairAddress`。
2. 第一版不使用 symbol 作为唯一标识，避免同名代币误判。
3. 价格判断优先读取固定主池，避免未来因为自动切换池子导致提醒误触发。

## 3. 外部依赖

### 3.1 DEX Screener

第一版只接 DEX Screener 官方 API。

优先使用的接口：

1. `GET /token-pairs/v1/{chainId}/{tokenAddress}`
   用途：查询某个 token 在指定链上的池子列表，初始化或校验主池。
2. `GET /latest/dex/pairs/{chainId}/{pairId}`
   用途：轮询固定主池的实时价格、流动性、成交量、24h 变动等信息。

当前 AIDOG 对应调用示例：

```text
GET https://api.dexscreener.com/token-pairs/v1/base/0x80394ae69f14444605032a7f2d74c8ab7d16a51d
GET https://api.dexscreener.com/latest/dex/pairs/base/0xDaAe8AfdEb4d31e4F6A0cDB9d490D4188d48C0A9
```

设计约束：

1. DEX Screener 文档当前给出的 `token-pairs` 和 `pairs` 相关接口限流为 `300 requests/minute`。
2. DEX Screener 的数据来自链上索引，存在短暂延迟和波动，提醒模块不能假设每一跳价格都绝对稳定。
3. 如果接口返回空池、空价格或异常流动性，当前轮询结果不应直接触发提醒。

### 3.2 飞书

第一版只接飞书群机器人 Webhook。

配置项：

- `FEISHU_WEBHOOK_URL`
- `FEISHU_SECRET`，如果机器人启用了签名校验则必填

## 4. 第一版功能范围

### 4.1 提醒类型

支持两类规则：

1. 价格阈值提醒
   - 当 `current_price_usd <= target_price_usd` 时触发
2. 时间窗口涨跌幅提醒
   - 当 `change_percent >= target_percent` 时触发上涨提醒
   - 当 `change_percent <= -target_percent` 时触发下跌提醒

### 4.2 时间窗口

第一版建议只支持预设窗口，不开放完全自由输入：

- `5m`
- `15m`
- `1h`
- `4h`
- `24h`

原因：

1. 预设窗口更容易和采样频率对齐。
2. 便于后续做查询索引和回测。
3. 可以避免用户设置过短窗口导致抖动过大。

### 4.3 触发规则

所有提醒按“穿越阈值”触发，不按“持续满足条件”重复发送。

示例：

1. 用户设置价格提醒 `<= 0.0040`
2. AIDOG 从 `0.0042` 跌到 `0.0039`，触发一次
3. 如果价格持续停留在 `0.0040` 以下，不重复提醒
4. 只有当价格先恢复到阈值上方，再次跌破阈值时，才允许下一次触发

### 4.4 冷却时间

每条规则都带冷却时间，第一版默认 `30 分钟`。

作用：

1. 避免接口抖动导致短时间重复通知
2. 避免价格围绕阈值来回震荡时刷屏

## 5. 模块拆分

建议按下面 5 个模块拆分。

### 5.1 Token Registry

职责：

1. 保存固定监控资产配置
2. 保存主池信息
3. 提供给后续模块统一读取

第一版可以直接硬编码或写入配置文件：

```json
{
  "symbol": "AIDOG",
  "chainId": "base",
  "tokenAddress": "0x80394ae69f14444605032a7f2d74c8ab7d16a51d",
  "pairAddress": "0xDaAe8AfdEb4d31e4F6A0cDB9d490D4188d48C0A9",
  "dexId": "uniswap",
  "quoteSymbol": "VIRTUAL"
}
```

### 5.2 DEX Screener Client

职责：

1. 封装官方 API 调用
2. 处理超时、重试、限流和响应校验
3. 将原始响应转换为内部标准结构

内部统一返回结构建议：

```json
{
  "symbol": "AIDOG",
  "chainId": "base",
  "tokenAddress": "0x80394ae69f14444605032a7f2d74c8ab7d16a51d",
  "pairAddress": "0xDaAe8AfdEb4d31e4F6A0cDB9d490D4188d48C0A9",
  "priceUsd": 0.0044,
  "priceNative": 0.006255,
  "liquidityUsd": 631552.68,
  "volume24h": 16021.31,
  "priceChange24h": -5.91,
  "sampledAt": "2026-02-27T00:00:00Z",
  "raw": {}
}
```

### 5.3 Price Snapshot Store

职责：

1. 按轮询频率保存价格快照
2. 提供某个时间窗口起点附近的价格查询
3. 为涨跌幅计算提供输入

建议采样频率：

- `30 秒` 一次

原因：

1. 对单币种提醒已经足够
2. 远低于 DEX Screener 免费接口限流
3. 可兼顾 5 分钟窗口和 24 小时窗口

### 5.4 Alert Engine

职责：

1. 读取用户配置的提醒规则
2. 根据当前价格和历史快照判断是否命中
3. 管理规则状态、重置状态和冷却时间

### 5.5 Notifier

职责：

1. 发送飞书消息
2. 记录通知结果
3. 做失败重试和错误日志

## 6. 数据流

完整链路如下：

1. Scheduler 每 30 秒触发一次轮询任务
2. DEX Screener Client 请求固定主池数据
3. 对响应做校验
4. 将有效价格写入快照表
5. Alert Engine 读取启用中的提醒规则
6. 对每条规则计算当前是否触发
7. 若触发，先检查冷却状态和是否已经处于已触发状态
8. 满足发送条件时调用飞书通知
9. 记录提醒事件和发送结果

## 7. 涨跌幅计算规则

自定义时间窗口涨跌幅不依赖 DEX Screener 返回的 `h1/h6/h24` 字段做核心判断，系统自己计算。

计算公式：

```text
change_percent = ((current_price - base_price) / base_price) * 100
```

其中：

- `current_price`：当前轮询价格
- `base_price`：窗口起点价格

窗口起点价格选取规则：

1. 目标窗口结束时间为当前时间
2. 从快照表中找到 `<= 当前时间 - 窗口时长` 的最近一条价格
3. 若该条价格缺失或距离目标时刻过远，则本轮不判定该规则

示例：

1. 当前时间 `10:30:00`
2. 规则窗口 `15m`
3. 目标起点时间 `10:15:00`
4. 若最近可用快照是 `10:14:45`，则使用该价格作为基准价

## 8. 提醒规则状态机

每条规则建议维护以下状态：

- `enabled`
- `armed`
- `triggered`
- `cooling_down`
- `disabled`

状态说明：

1. `armed`
   表示当前允许触发
2. `triggered`
   表示本次已经命中并已发送提醒
3. `cooling_down`
   表示命中后处于冷却时间内，不允许重复提醒

价格规则重置条件：

1. 价格提醒在价格重新回到阈值上方时重置为 `armed`

涨跌幅规则重置条件：

1. 上涨提醒在涨幅回落到阈值以下时重置
2. 下跌提醒在跌幅回升到阈值以上时重置

## 10. 接口设计

第一版可以先只做内部管理接口，不做前端页面。

### 10.1 创建价格提醒

```http
POST /api/alerts/price-below
```

请求示例：

```json
{
  "symbol": "AIDOG",
  "targetPriceUsd": 0.0040,
  "cooldownSeconds": 1800
}
```

### 10.2 创建涨跌幅提醒

```http
POST /api/alerts/change-percent
```

请求示例：

```json
{
  "symbol": "AIDOG",
  "direction": "down",
  "window": "15m",
  "targetPercent": 5,
  "cooldownSeconds": 1800
}
```

### 10.3 查询当前资产状态

```http
GET /api/assets/aidog/status
```

返回内容建议包含：

1. 当前价格
2. 主池地址
3. 最近采样时间
4. 已启用规则列表
5. 最近一次提醒记录

## 11. 飞书消息格式

第一版用文本消息即可。

价格提醒示例：

```text
[AIDOG 价格提醒]
链: Base
当前价格: 0.00398 USD
触发条件: 价格 <= 0.00400 USD
主池: 0xDaAe8AfdEb4d31e4F6A0cDB9d490D4188d48C0A9
时间: 2026-02-27 20:30:00 UTC+8
```

涨跌幅提醒示例：

```text
[AIDOG 涨跌幅提醒]
链: Base
当前价格: 0.00410 USD
窗口: 15m
基准价格: 0.00435 USD
当前涨跌幅: -5.75%
触发条件: 15m 跌幅 >= 5%
主池: 0xDaAe8AfdEb4d31e4F6A0cDB9d490D4188d48C0A9
时间: 2026-02-27 20:45:00 UTC+8
```

## 12. 异常与边界条件

### 12.1 DEX Screener 返回空数据

处理：

1. 本轮记录错误日志
2. 不写入快照
3. 不执行提醒判定

### 12.2 价格字段缺失或为 0

处理：

1. 标记为无效样本
2. 不触发提醒

### 12.3 流动性过低

第一版建议配置一个最小流动性阈值，例如 `10000 USD`。

处理：

1. 若低于阈值，则跳过提醒判定
2. 日志中记录“价格源流动性不足”

### 12.4 连续失败

处理：

1. 连续 3 次取价失败时，发送一条系统异常通知到飞书
2. 恢复成功后发送一条恢复通知

## 13. 实现顺序

建议按下面顺序开发：

1. 固定写死 AIDOG 资产配置
2. 实现 DEX Screener Client
3. 实现价格轮询和快照落库
4. 实现价格阈值提醒
5. 实现自定义窗口涨跌幅提醒
6. 接飞书通知
7. 增加异常监控和日志

## 14. 第一版验收标准

满足以下条件即可认为 AIDOG 模块跑通：

1. 系统能稳定轮询 AIDOG 主池价格
2. 系统能持续写入价格快照
3. 可以创建一条价格阈值提醒并成功触发飞书消息
4. 可以创建一条 15 分钟跌幅提醒并成功触发飞书消息
5. 同一条规则不会在阈值内持续重复提醒
6. 接口异常时不会产生误报
